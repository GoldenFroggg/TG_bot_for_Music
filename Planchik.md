## ПЛАН ДЕКОМПОЗИЦИИ ПРОЕКТА «MUSIC ASSISTANT BOT»

### ЗАДАЧА 1 — КАРКАС ЧАТ-БОТА

- Реализовать каркас чат-бота (aiogram).
- Команды start, help.
- /help — список доступных команд.
- /help <command> — справка по конкретной команде.
- (!) Добавить модульные тесты.

##### Регламент отдельно подчёркивает, что начиная со второй задачи слой работы с музыкальными данными должен быть отделён от конкретного API (Spotify/Last.fm) через общий интерфейс — источник данных должен быть заменяем без переписывания хэндлеров.

### ЗАДАЧА 2 — ПОИСК ТРЕКА И БАЗОВАЯ ИНФОРМАЦИЯ

- Реализовать команду /track.
- Обычное текстовое сообщение (без команды) как поисковый запрос.
- Получение метаданных трека: исполнитель, альбом, год выпуска, жанр.
- Обработка «трек не найден», неоднозначный запрос, ошибка/лимиты API.
- (!) Добавить модульные тесты.

### ЗАДАЧА 3 — ПОХОЖИЕ ТРЕКИ

- Реализовать команду /similar.
- Определить признаки схожести (жанр, исполнитель, теги источника).
- Реализовать формирование подборки (N похожих треков).
- Форматирование ответа: карточка трека + список похожих.
- (!) Добавить модульные тесты.

### ЗАДАЧА 4 — ХРАНЕНИЕ И КЭШИРОВАНИЕ

- Спроектировать схему SQLite (пользователи, история запросов, кэш треков).
- Реализовать слой доступа к БД (инициализация/миграции при первом запуске).
- Кэширование ответов API для повторных запросов.
- (!) Не забыть про TTL кэша — музыкальные метаданные меняются редко, но не никогда.
- (!) Добавить модульные тесты.

### ЗАДАЧА 5 — ПЕРСОНАЛИЗАЦИЯ

- Реализовать историю запросов пользователя.
- Реализовать «избранное» (сохранение понравившихся треков).
- Учитывать историю пользователя при подборе похожих треков (не только последний запрос).
- (!) Добавить модульные тесты.

### ЗАДАЧА 6 — UX И ИНТЕРАКТИВНОСТЬ

- Инлайн-кнопки: «Ещё похожий», «Найти заново», «В избранное».
- Пагинация длинных списков похожих треков.
- Форматирование сообщений (Markdown/HTML, эмодзи — как заявлено в README).
- (!) Проверка, что ответ укладывается в целевые «пару секунд» (иначе — индикатор загрузки).
- (!) Добавить модульные тесты.

### ВОЗМОЖНОЕ ДАЛЬНЕЙШЕЕ РАЗВИТИЕ

- Генерация плейлиста по настроению/сессии прослушивания.
- Поддержка нескольких языков интерфейса.
- Другие платформы (аналог мультиплатформенности из карточного проекта).
- Совместные/социальные функции — делиться треком или подборкой с другим пользователем.
- A/B-тестирование алгоритма подбора похожих треков.
